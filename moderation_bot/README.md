# 🛡 Бот адаптивной модерации группы (aiogram 3.x)

Telegram-бот, который удаляет из группы нежелательные сообщения по правилам, включаемым
администратором прямо в чате: сообщения от конкретного бота/пользователя, сообщения с
запрещённым хэштегом и медиафайлы (в том числе от всех, кроме админов).

* Хранилище настроек — **SQLite** (`aiosqlite`, WAL, отдельные настройки на каждую группу).
* Панель администратора — **`/settings`** с инлайн-кнопками (доступна только админам группы).
* Модульная структура: правила фильтрации — чистые функции, бизнес-логика — в сервисах,
  хэндлеры — тонкие; **128 тестов** (pytest + pytest-asyncio), линтер `ruff` без замечаний.

## 1. Быстрый старт

> 📖 Первый запуск впервые? Пошаговая инструкция с картинками Telegram-интерфейса —
> в **[SETUP.md](SETUP.md)** (токен у @BotFather, права в группе, автозапуск, разбор ошибок).
> Ниже — короткая версия.

```bash
# 1. Перейти в каталог бота
cd moderation_bot

# 2. Виртуальное окружение и зависимости
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 3. Настроить конфиг
cp .env.example .env
nano .env                          # вставить BOT_TOKEN (и при желании поменять фильтры)

# 4. Запустить
python -m bot
```

Бот запущен, если в логе появилось:

```
2026-01-01 12:00:00 | INFO     | bot.app | Бот запущен: @my_moderation_bot (id=123456789)
2026-01-01 12:00:00 | INFO     | bot.app | Фильтры: польз.=@zaztagbot | хэштег=#реклама | чат=все группы
```

Проверить готовность перед запуском:

```bash
python manage.py selftest     # Python, зависимости, .env, токен, база, связь с Telegram
python manage.py demo         # что бот сделает с типовыми сообщениями (без Telegram)
```

Тот же запуск через `make`: `make setup` (зависимости + `.env` + диагностика), затем `make run`.

### Что нужно сделать в Telegram (один раз)

1. **Создать бота:** [@BotFather](https://t.me/BotFather) → `/newbot` → скопировать токен в `BOT_TOKEN`.
2. **Добавить в группу:** Настройки группы → Участники → Добавить участника.
3. **Выдать права администратора** с включённым правом **«Удалять сообщения»** — без него
   `message.delete()` вернёт ошибку и фильтры фактически не сработают.
   Проверить права можно командой: `python manage.py doctor --chat <ID группы>`.
4. **Отключить приватность бота** (иначе бот видит только команды, но не обычные сообщения):
   `@BotFather` → `/setprivacy` → выбрать бота → **Disable**.
5. В группе отправить **`/settings`** и включить нужные фильтры кнопками.

## 2. Команды и панель

| Команда | Что делает |
|---|---|
| `/settings` | Панель с инлайн-кнопками всех фильтров. Только для администраторов группы. |
| `/rule` | То же, что `/settings` (короткий вызов). |
| `/help` | Справка и текущий статус фильтров. |

Панель `/settings` выглядит так:

```
🛡 Модерация группы
Чат: -1001234567890
Включено фильтров: 3 из 4

Переключатели — нажмите кнопку, чтобы включить или выключить:
✅ вкл — Сообщения от @zaztagbot
✅ вкл — Хэштег #реклама
✅ вкл — Медиа от @zaztagbot
❌ выкл — Медиа от не-админов

[✅ Сообщения от @zaztagbot]   ← кнопки
[✅ Хэштег #реклама]
[✅ Медиа от @zaztagbot]
[❌ Медиа от не-админов]
[🔄 Обновить] [♻️ Сбросить]
```

* Каждое нажатие сразу пишется в SQLite и перерисовывает панель.
* Настройки **отдельные для каждой группы** — можно управлять несколькими чатами одним ботом.
* Не-администратору команда не покажет панель: бот ответит автоудаляемым сообщением
  «⛔ Команда доступна только администраторам группы».
* Проверка прав на нажатие кнопки делается заново — если админ потерял права, кнопки перестанут работать.

## 3. Правила модерации

| Фильтр в БД | Что удаляет | Цель правила |
|---|---|---|
| `block_target_user` | любое сообщение от `TARGET_USERNAME` (по @username, регистр не важен) | `zaztagbot` |
| `block_hashtag` | сообщения с текстом `BANNED_HASHTAG` в тексте или в подписи к медиа | `#реклама` |
| `block_media_from_target` | фото / видео / GIF / «кружки» от `TARGET_USERNAME` | `zaztagbot` |
| `block_media_non_admin` | фото / видео / GIF / «кружки» от всех, кроме администраторов группы | все, кроме админов |

Порядок проверок (срабатывает **первое** совпавшее правило):

1. сообщение от target-пользователя;
2. в сообщении есть запрещённый хэштег;
3. медиа от target-пользователя;
4. медиа от не-администратора.

Важные детали:

* Сообщение удаляется **сразу** через `message.delete()`; дополнительно бот может отправить
  короткое уведомление о причине (оно самоудаляется через 6 секунд) — управляется `NOTIFY_ON_DELETE`.
* Правила 3 и 4 не применяются к администраторам группы: админ может спокойно отправлять картинки.
* Хэштег ищется «устойчиво»: `#реклама`, `# Реклама`, `#РЕКЛАМА!!!`, а также в подписи к фото.
* Сообщения без автора (анонимный админ, запись от имени канала), сообщения самого бота и личные
  сообщения боту модерация не трогает.
* Если у бота нет права «Удалять сообщения», ошибка Telegram попадает в лог, но обработка
  остальных сообщений продолжается.

## 4. Настройки в `.env`

| Переменная | По умолчанию | Описание |
|---|---|---|
| `BOT_TOKEN` | — | **Обязательно.** Токен от @BotFather. |
| `TARGET_USERNAME` | `zaztagbot` | @username без `@`, сообщения которого удаляются. |
| `BANNED_HASHTAG` | `#реклама` | Запрещённый хэштег (пробелы и регистр не важны). |
| `ALLOWED_CHAT_ID` | пусто | Ограничить бота одной группой (её ID). Пусто — работать во всех группах. |
| `NOTIFY_ON_DELETE` | `true` | Отвечать ли в чат на удаление (ответ самоудаляется). |
| `VERBOSE_LOG` | `true` | Логировать ли удалённые сообщения. |
| `ADMIN_CACHE_TTL` | `300` | Секунды кэша проверки «админ ли автор» (экономит вызовы API). |
| `DB_PATH` | `data/moderation.sqlite3` | Путь к базе (относительный — от каталога `moderation_bot`). |
| `FORWARD_DELETED_TO_LOG` | `false` | Копировать удалённые сообщения в лог-чат. |
| `LOG_CHAT_ID` | пусто | ID канала/чата для копий удалённых сообщений. |

Значения по умолчанию для новых групп задаются в `bot/models.py` → `SettingsDefaults`.

## 5. CLI: настройка без Telegram

Иногда удобнее поставить фильтры из консоли (например, при первом развёртывании):

```bash
python manage.py list                                  # настройки всех чатов в базе
python manage.py show     --chat -1001234567890        # настройки конкретной группы
python manage.py set      --chat -1001234567890 --flag block_media_non_admin --value on
python manage.py set      --chat -1001234567890 --flag block_hashtag --value off
python manage.py doctor   --chat -1001234567890        # проверить токен, доступ к чату и права бота
python manage.py demo                                  # показать, что бот сделает с примерами сообщений
python manage.py selftest                              # диагностика готовности к запуску
python manage.py selftest --delete-webhook             # снять вебхук, мешающий long polling
```

`selftest` работает даже с пустым `.env`: он последовательно проверяет Python и зависимости,
файл настроек, формат токена, доступность базы и (если токен рабочий) связь с Telegram,
наличие вебхука и права бота в чате из `ALLOWED_CHAT_ID`, а в конце перечисляет,
что осталось сделать.

`demo` работает без обращения к Telegram и удобен, чтобы проверить правила до запуска:

```
Демонстрация правил (значения по умолчанию): цель=@zaztagbot, хэштег=#реклама

✅ оставить                                   | @friend          | Привет! Как дела?
🗑 УДАЛИТЬ — сообщение содержит запрещённый... | @spammer         | Срочная продажа курса #реклама
🗑 УДАЛИТЬ — сообщение от заблокированного... | @zaztagbot (бот) | Подпишись на канал
🗑 УДАЛИТЬ — сообщение от заблокированного... | @zaztagbot (бот) | [фото]
✅ оставить                                   | @spammer         | [фото]
🗑 УДАЛИТЬ — сообщение содержит запрещённый... | @friend          | Свежий мем #реклама
```

ID группы можно увидеть в панели `/settings` (строка «Чат: …»), в логах бота или в `doctor`.

## 6. Тесты и качество кода

```bash
pip install -r requirements-dev.txt
pytest                 # 128 тестов: правила, БД, сервисы, панель, хэндлеры на реальном Dispatcher, CLI
ruff check .           # линтер
ruff format .          # форматирование
```

Тесты не обращаются к сети: вместо Telegram используется `tests/fakes.py` (`FakeBot`),
а сообщения — настоящие объекты `aiogram.types.Message`, так что проверяется и совместимость
с API библиотеки.

```
moderation_bot/
├── bot/
│   ├── __main__.py        # точка входа: python -m bot

│   ├── texts.py           # тексты панели и справки
│   ├── callbacks.py       # CallbackData-фабрики
│   ├── middlewares.py     # ограничение работы одним чатом (ALLOWED_CHAT_ID)
│   ├── compat.py          # совместимость разных версий aiogram 3.x
│   ├── logging_setup.py   # настройка логов
```

## 8. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| Фильтры не срабатывают, в логе «Не удалось удалить сообщение» | Бот не администратор или у него выключено право «Удалять сообщения». Проверьте: `python manage.py doctor --chat <ID>`. |
| Бот реагирует только на команды, обычные сообщения не видит | Включён режим приватности. `@BotFather` → `/setprivacy` → Disable (после этого перезапустить бота/перепригласить). |
| `❌ Ошибка конфигурации: BOT_TOKEN не задан` | Нет файла `.env` или в нём остался токен-заглушка. `cp .env.example .env` и вставьте настоящий токен. |
| Любая проблема при настройке | Запустите `python manage.py selftest` — он проверяет всё по шагам и пишет, что именно исправить. Полный разбор — в [SETUP.md](SETUP.md). |
| Панель не открывается участнику | Команда доступна только администраторам группы — так и задумано. |
| Сообщения от target-бота не удаляются | У бота нет @username или он отличается от `TARGET_USERNAME`. Уточните юзернейм в профиле и поправьте `.env`, затем перезапустите бота (`TARGET_USERNAME` — это настройка запуска, а не per-chat флаг). |
| Нужно заблокировать другого бота | Поменяйте `TARGET_USERNAME` в `.env` и перезапустите бота. Подписи кнопок обновятся, логика — тоже. |

## 9. Заметки по эксплуатации

* База — один файл `data/moderation.sqlite3` (+ `-wal`, `-shm`). Для бэкапа достаточно скопировать
  файл при остановленном боте (или использовать `sqlite3 .backup`).
* Бот работает в режиме long polling: вебхук и внешний домен не нужны. Держать его можно
  на любом VPS; для продакшена удобно обернуть в systemd:
  ```ini
  [Unit]
  Description=Telegram moderation bot
  After=network-online.target

  [Service]
  WorkingDirectory=/opt/moderation_bot
  ExecStart=/opt/moderation_bot/.venv/bin/python -m bot
  Restart=always
  RestartSec=5
  User=botuser

  [Install]
  WantedBy=multi-user.target
  ```
* Токен — секрет: `.env` уже в `.gitignore`, не коммитьте его.
* Один экземпляр бота нельзя запускать дважды одновременно (Telegram начнёт отдавать ошибки
  409 Conflict при long polling).
